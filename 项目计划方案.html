jikeai-clone 项目计划方案

AI 短剧 SaaS 平台复刻 · Vue3 + Go 全栈架构

一、项目概述

基于对「即刻AI」（jikeai.cc）的完整竞品分析，复刻其核心 AI 短剧创作链路：剧本 → 角色/场景/物品识别 → 批量生图 → 智能分镜工作台 → 视频生成。目标是用你现有的 RunningHub + Hypit 生态作为底层 AI 能力，搭建一个可自用、可分销的 Web 工作台。

二、技术选型

层级选型理由
前端框架Vue 3 + TypeScript + Vite生态成熟、构建快、与你现有前端经验匹配
UI 组件库Element Plus中后台场景标配，表格/表单/对话框开箱即用
状态管理PiniaVue3 官方推荐，TypeScript 友好
路由Vue Router 4标准选择
HTTP 客户端Axios带拦截器，方便统一注入 token / 错误处理
后端语言Go 1.22+你已选定；并发好、部署单二进制、适合 AI 任务队列
后端框架Gin轻量高性能，社区大
ORMGORMGo 生态最流行，支持 SQLite/PostgreSQL 切换
数据库SQLite（起步）→ PostgreSQL（上线）本地开发零依赖，上线平滑切换
配置管理Viper / YAML已内置 config.yaml
AI 能力对接OpenAI API + RunningHub API + 豆包 API分镜推理用 GPT、生图用 RunningHub G-2.5、生视频用 Seedance Mini

五、数据模型设计

5.1 Project（短剧项目）

  • ID, Name, Description, Status（草稿/制作中/已完成）
  • UserID, CreatedAt, UpdatedAt

5.2 Episode（剧集）

  • ID, ProjectID, EpisodeNumber, Title
  • ScriptText（原始剧本）, Status

5.3 Character / Scene / Item（识别结果）

  • Character: name, identity_anchor, costume_prompt, personality, appearance_cues, reference_image
  • Scene: name, spatial_anchor, lighting_prompt, time_of_day, reference_image
  • Item: name, category, prompt, reference_image

5.4 Storyboard（分镜）

  • ID, EpisodeID, FrameIndex
  • Text（人读脚本，~400字）, VideoPrompt（机读prompt，~1200字）
  • Roles[], Scenes[], Items[]（@-mention 引用）
  • VideoModel（doubao-seedance-2.0-mini）, VideoURL, Duration

六、开发排期

Phase 1：基础骨架（本周）

前后端项目跑通，Dashboard 可访问，项目 CRUD 接口联通。Go 安装完成后 go mod tidy + 启动。

Phase 2：剧本 + 识别（1-2 周）

接入 OpenAI API，实现「粘贴剧本 → 一键识别角色/场景/物品」，输出结构化 JSON 并入库。

Phase 3：生图 + 素材库（2-3 周）

对接 RunningHub G-2.5 API，给每个识别结果自动出参考图，支持手动换图/迭代。

Phase 4：分镜工作台（2-3 周）

实现三栏布局，两次 LLM 调用生成 text + video_prompt，支持 @-mention 拖拽引用。

Phase 5：视频生成 + 积分（1-2 周）

对接 Seedance Mini，批量生成视频，积分扣减闭环。

Phase 6：爆款转绘 + 上线（远期）

竞品链接解析、字幕擦除、分销链接生成。
